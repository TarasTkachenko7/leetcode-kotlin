# 0146. LRU Cache

- **Сложность:** Medium
- **Паттерн:** Design
- **Ссылка:** [LeetCode №146](https://leetcode.com/problems/lru-cache/)

## Идея
Для достижения времени выполнения $O(1)$ для операций `get` и `put` используется комбинация хэш-таблицы и двусвязного списка:
1. **Двусвязный список с фиктивными узлами (`head`, `tail`):**
    - Устраняет граничные проверки при добавлении в конец и удалении узлов.
    - Элементы упорядочены по времени последнего использования: узел сразу после `head` (`head.next`) — наименее востребованный (LRU), а узел перед `tail` (`tail.prev`) — самый свежий (MRU).
    - При каждом обращении (`get` или обновление в `put`) узел перемещается в конец списка (`moveToTail`).
2. **`HashMap<Int, Node>`:**
    - Хранит соответствие между ключом и ссылкой на узел списка, что позволяет находить узел за $O(1)$.
3. **Вытеснение (Eviction):**
    - Когда размер кэша достигает `capacity`, извлекается узел `head.next` через `removeLRU()`.
    - Благодаря полю `key`, сохраненному внутри узла `Node`, ключ удаляется из `map` за $O(1)$ без дополнительного поиска.

## Сложность
- **Time Complexity:**
    - `get(key)`: $O(1)$ — поиск по хэш-таблице и перепривязка 4 указателей в двусвязном списке.
    - `put(key, value)`: $O(1)$ — вставка/обновление в хэш-таблице и добавление/удаление узлов связного списка за константное время.
- **Space Complexity:** $O(\text{capacity})$ — память под хранение до $N$ узлов в двусвязном списке и ссылок на них в `HashMap`.
